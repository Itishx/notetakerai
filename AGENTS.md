# Braino repository instructions

## Documentation is part of the feature

Nothing meaningful is complete until it is documented in the Braino Knowledge Base.

Whenever you add or materially change a feature, mode, product, release, design decision, or technical system:

1. Create or update its internal Markdown page in `Braino Knowledge Base/`.
2. Create or update its permanent public page under `/knowledge`.
3. Register the page in `src/lib/brainoKnowledge.ts`.
4. Make sure it appears in **Everything New with Braino** on the master index.
5. Document purpose, simple usage, honest limitations, technical shape, status, and release date.
6. Write public copy in Itish Pande's style: clean, human, conversational, direct, and easy to understand.

Use `Braino Knowledge Base/templates/feature.md` as the starting point.

Treat missing documentation as unfinished implementation, not optional follow-up work.
